# AGENTS.md 및 프로젝트 구조 분석

## 이번 범위와 문서 근거

최신 사용자 지시는 **보험 제외, 증권 데이터 준비 진행**입니다. AGENTS.md의 보험 범위보다 이 지시를 우선합니다.
초기 작업은 Phase 1 감사였으며, 이어서 상품 정규화·검색 텍스트와 평가용 라벨 준비까지 구현했습니다.
원본 수정·압축 해제·외부 수집·임베딩·UI 구현은 수행하지 않았습니다.
`data/processed/audit/`에는 감사 통계를, `data/processed/`에는 정규화 상품과 별도 평가 질문·검토 대상을 저장합니다.

AGENTS.md의 데이터 설명서 수치는 참고값이며 현재 확보된 파일의 실측값과 구분합니다.
AGENTS.md에서 언급한 요구사항 PDF와 데이터 설명서 HWP는 현재 프로젝트에 없습니다.
원문 두 문서와 NF2001~NF2007의 상세 내용을 직접 대조했다고 주장하지 않습니다.

## 프로젝트 구조 분석

작업 시작 시 `README.md`(프로젝트명만 기재), 사용자 제공 `AGENTS.md`, 원본 ZIP 8개가 있었습니다.
`src/`, `scripts/`, `tests/`, `docs/`, 의존성 목록, 앱 코드, 설정 파일은 없었습니다.
원본 폴더는 다음 구조입니다.

```text
data/raw/
├── products/securities/
│   ├── TS_1.상품_1.증권_01.주식형.zip
│   ├── TS_1.상품_1.증권_02.채권형.zip
│   ├── TS_1.상품_1.증권_03.재간접.zip
│   ├── TS_1.상품_1.증권_04.단기금융.zip
│   ├── TS_1.상품_1.증권_05.파생형.zip
│   └── TS_1.상품_1.증권_06.퇴직연금.zip
└── labels/
    ├── training/TL_1.CoT_1.증권_03.상품 비교 추천형.zip
    └── validation/VL_1.CoT_1.증권_03.상품 비교 추천형.zip
```

상품은 Training만, 라벨은 Training/Validation의 증권 상품 비교 추천형만 있습니다.
보험, 합성 소비자 CSV, Test, 다른 라벨 질문유형, 원문 PDF는 현재 입력에 없습니다.
설명서의 전체 규모 또는 세 분할 중복 설명을 현재 부분 데이터의 실측 사실로 대입하면 안 됩니다.

추가한 구성은 다음과 같습니다.

```text
scripts/audit_data.py                 # 표준 라이브러리 기반 CLI 및 감사 로직
scripts/prepare_data.py               # 감사→증권 정규화→라벨 연결 CLI
src/ingestion/normalize.py            # 순수 변환/정형 파싱/중복/라벨 분리
tests/test_audit_data.py              # 합성 fixture로 감사/원본 보존 검증
tests/test_normalize.py               # 금융 파싱·ID·라벨 분리 단위 테스트
tests/test_prepare_data.py            # ZIP→산출물 통합 테스트
docs/data_audit.md                    # CLI가 생성한 전체 실측 보고서
docs/data_preparation.md              # 실제 전처리 결과·미확인 필드 집계
docs/requirements.md                 # 현재 문서
docs/evidence/audit_verification.json # 실제 데이터 재실행 검증
docs/evidence/preparation_verification.json # 전처리 원문/연결/재실행 검증
data/processed/                       # 상품·평가 질문·검토·manifest, Git 제외
.env.example                         # 이후 단계용 설정 예시
.gitignore                           # 원본/산출물/환경변수 제외
```

감사 로직은 스크립트에 두고 전처리 CLI에서 동일 파서/분류기를 재사용합니다.
금융 속성 정규화는 `src/ingestion/normalize.py`의 독립 함수로 분리했습니다. 빈 앱/색인 모듈은 만들지 않았습니다.
README는 기존 UTF-16에서 UTF-8로 변경하고 실행법을 추가했습니다.

## 전처리에 반영할 실측 결과

상세 수치와 개별 이슈 경로는 `data_audit.md`와 로컬 manifest가 기준입니다.

- 상품 8,000건, 라벨 2,147건. 모두 UTF-8로 엄격 디코딩되는 최상위 JSON 객체입니다.
- 상품은 11개 문자열 필드가 공통이며 빈값/누락이 없습니다. `pdf_filename`, 회사, 확정 원본 상품 ID, 수익률 기준일 필드는 없습니다.
- 원금보장 필드의 원문은 모두 `원금 비보장형`입니다. 원금보장 필수 조건에 적격 상품이 있다고 가정할 수 없습니다.
- 라벨 `cot_id`, `step_count`는 정수, `age`는 문자열입니다. `product_names`는 배열 2,145건과 불완전 문자열 2건이 혼재합니다.
- 라벨 상품명 참조 5,016개 중 5,010개가 원문 이름으로 연결되며 6개는 미연결입니다. 불완전 문자열 2건은 참조 수에서 제외합니다.
- ZIP 멤버 11개는 `.json `으로 끝납니다. 모두 `/`로 시작하므로 향후 압축 해제 기능에는 안전한 경로 정책이 필요합니다.
- 전략에는 Office escape, 사설영역 글리프, 대체문자, 제어문자와 공백이 있습니다. 원문과 정리본을 분리해야 합니다.
- 수익률의 `6개월`, `1년` 표시는 기간입니다. 현재 수익률 또는 기준일로 해석할 수 없습니다.
- 콘텐츠 중복 및 라벨 학습/검증 콘텐츠·cot_id 교집합은 0입니다. 상품 분할 간 중복은 Training만 있어 검증할 수 없습니다.

불완전 문자열이나 미연결 이름을 임의로 고치지 않았습니다. 파서는 평가 가능 라벨 2,140건과 검토 라벨 7건을 분리합니다.
상품은 원문을 보존하면서 정리본과 정형 파싱 값을 생성합니다. 수익률 89건·만기 7건은 파싱을 확정하지 않았습니다.
미제공 회사·가입 조건을 상품명에서 임의 확정하지 않습니다. 미연결 원문 PDF와 수익률 기준일은 계속 미확인입니다.

## 요구사항 추적 및 남은 작업

| 항목 | 현재 상태 | 후속 완료 조건 |
| --- | --- | --- |
| Phase 1 감사 | 스크립트·전체 보고서·검증 구현 | 추가 데이터 확보 시 재감사 |
| F2001 | 상품 8,000건 정규화·1건→1검색 텍스트 구현/검증 | 문서·색인은 별도 요구사항으로 진행 |
| F2002 | 미구현 | Chroma upsert 및 2회 색인 중복 없음 |
| F2003 | 미구현 | 공식명 포함 검색어 LLM 구조화 출력 |
| F2004~F2005 | 미구현, 원문·사용권 확보 필요 | 실제 문서 수집/선별/캐시 및 별도 색인 |
| F2006~F2008 | 미구현 | 두 컬렉션 검색, retrieve→generate, 유효 인용 |
| F2009~F2012 | 미구현 | 상품별 대화, 비교/탐색, 상태·금융 안내 UI |
| NF2001~NF2007 | 원문 명세 미확보 | 실제 요구사항 PDF 확보 후 상세 추적 |
| F2013~F2016 | 착수 전 | 필수 요구사항 검증 후 선택 수행 |

이용 조건, 외부 LLM 전송 가능 범위, 원문 링크 정합성은 미확인입니다.
이번 작업에서 외부 검색이나 데이터 전송은 하지 않았습니다.
